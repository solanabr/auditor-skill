# Changelog

What each release of auditor-skill added, newest first. The README's [What's new](../README.md#whats-new) gives each release in one line. Back to the [docs index](README.md).

A patch release (X.Y.Z) moves only the plugin's version, which plugin users receive when they update the plugin; a minor release (X.Y.0) moves every version reference and is tagged with a GitHub Release ([docs/CONTRIBUTING.md §3](CONTRIBUTING.md#3-branch-and-pr-flow)). The entries name the pull requests they come from.

## 7.7 (7.7.0 to 7.7.4, November 2026)

7.7.0 is the minor release that closes the 7.6.x patch series: the patches 7.6.2 to 7.6.9 (#47 to #54) merged with it on 2026-11-04, as one stack. The host-kernel coverage (#58) merged before 7.7.2 and left the version as it was, so it shipped with 7.7.2 (#70, 2026-11-09). #70's description calls that content 7.7.1, a version that was never published.

### 7.7.4 (#72)

- **SQLite 3.54 in the Rust tools.** `tools/auditor-tools`, where `audit-mem` keeps its store in SQLite, bundles SQLite 3.54.1 through rusqlite 0.41.0 and libsqlite3-sys 0.39.1, in place of SQLite 3.46 through rusqlite 0.32.1. That clears RUSTSEC-2026-0459: SQLite before 3.54.0 can return uninitialized page-cache memory when it opens a database with a `-wal` file beside it whose page size differs. `audit-mem` never opened such a pair, since it refuses a store in WAL mode or with a `-wal` or `-shm` file beside it before SQLite opens it. Building `audit-scan` and `audit-mem` now needs Rust 1.89 or newer, rusqlite 0.41's floor; `audit-logs` alone keeps 1.82. Rebuild the tools after the update, as after every update.

### 7.7.3 (#71)

- **Three depths and a CI mode.** The README and docs start from what you want checked: Quick (`/auditor:diff-audit`, `/auditor:quick-scan`, `/auditor:deep-review`), Standard (`/auditor:audit <path> --scope …`) and Full (`/auditor:audit-cycle` or `/auditor:audit-assist`, then `/auditor:re-audit`). The scopes are defined once, in SKILL.md, and intake is part of Full only. quick-scan and diff-audit, in CI too, read the declared selection of `references/depth-scope.md`, written first to `audit_<n>/scope.md`, and diff-audit reviews at most 5,000 changed lines, riskiest first; `--over-budget fail` fails a larger change instead. Each Quick command writes a report in its run directory (`PR-REPORT.md`, `QUICK-SCAN.md`, `DEEP-REVIEW-<unit>.md`). `--ci` on `diff-audit` and `quick-scan` runs them unattended, with `--fail-on <N>` for the threshold: they write `audit_<n>/findings.json` and end with one verdict line, and `templates/ci/auditor-pr.yml` runs the analyzers on every pull request and Quick on those from your own branches ([docs/ci.md](ci.md)). On a public repository CI publishes pass/fail and notes about the tools only, and no longer fails a job for want of a private channel. In diff-audit, interactive or with `--ci`, a changed lockfile gets checklist 11 §11.11's CI budget: `lock-delta.sh --run <R> set` finds the new versions, and `deps.sh lock-budget` checks their publish ages and compares the published code of every changed key handler and at most 40 others. The CI verdict requires `deps-artifacts` as well as `lock-delta` when a `Cargo.lock`, `package-lock.json`, `npm-shrinkwrap.json`, `yarn.lock` or `bun.lock` changes. `AUDITOR_PUBLISH_AGE`, on by default, adds traffic: a review of a lockfile change sends the name of each package its set holds, new packages and new versions alike, to its public registry (npmjs.org, crates.io's index, pypi.org), and each crate the budget selects to crates.io's record as well, with one disclosure row per service. With it off, the review still fetches the published code of the versions its budget selects. docs/costs.md now gives the measured cost and time of each depth, in place of April 2026's estimates.
- **Every report says how it was made.** Its Generated line, which `rundir.sh stamp` prints right before the report is written, names the version and the UTC time, and says that no person reviewed the report unless `AUDITOR_REVIEW_STATEMENT` holds the review you set. The client report no longer claims a manual review by default.
- **CI pins a commit on `main`.** `AUDITOR_SKILL_COMMIT` in `templates/ci/auditor-pr.yml` takes the full id of an auditor-skill commit on `main`, such as the merge commit that shipped the release you use, since no release tag holds the template yet and patch releases get no tag. Both jobs fetch exactly that commit and stop when it does not match. Once a tag holds the template, `git ls-remote https://github.com/solanabr/auditor-skill 'refs/tags/<tag>^{}'` prints the commit it names: the tags are annotated, and both jobs reject a tag's own id ([ci.md](ci.md#setup)).
- **Measured costs.** docs/costs.md's runs were measured from 2026-11-08 to 2026-11-10 with `claude-opus-5-5`, on 3K-, 7K- and 12K-line programs: Quick about $2 to $8 in 4 to 23 minutes, Standard about $13 to $19 in 36 to 56 minutes, and Full $19.52 in an hour, run once, on the 3K-line program. On the shipped text a diff-audit cost $8.10 in 19 minutes for a 7,830-line range of the 3K-line repository that adds a lockfile, and $3.99 in 9 minutes for a narrow change of 1,248 lines to the 12K-line program; a quick-scan of the 3K-line repository cost $6.98 in 23 minutes. The CI template caps a review at $15 ([docs/costs.md](costs.md#cost-and-time-by-depth)).

### 7.7.2 (#70, and #58 before it)

- **Strict mode is opt-in.** By default the checks that used to stop a run print a note instead: the run goes on, and the report lists each note under Coverage & Limitations. Only the few shapes still refused in both modes stop it; Rules 11e and 11f list them. Builds and PoCs run natively unless intake, `AUDITOR_EXEC_MODE` or strict mode says otherwise, and nothing asks for the execution mode mid-run. Strict mode, for code you don't trust, keeps the refusals and builds only in isolated mode: `AUDITOR_STRICT=1`, `--strict` on a command, or intake's "Untrusted source" answer turns it on, and the launch line with `templates/strict-settings.json` gives its full effect ([OUTPUT-RULES.md Rule 11f](../OUTPUT-RULES.md#11f--default-and-strict-mode)).
- **Anchor builds and other fixes.** In 7.7.0 an `anchor` installed through avm did not start in the build's own HOME, Anchor 1.x builds failed at the IDL step, Anchor 1.2 got the wrong platform tools, and `target.sh` always passed `--ignore-keys`, which anchor-cli 0.31.1 rejects. 7.7.2 fixes all four: avm's `anchor` finds its releases, the IDL is built in a step of its own, the platform tools are the ones Anchor asks for, and `--ignore-keys` goes only to an `anchor build` whose help lists it. It was verified with anchor-cli 1.0.2, 1.1.2 and 1.2.0 through avm 1.1.2, and with 0.31.1 from its release binary. An older `cargo build-sbf` builds natively, offline, in the runners' throwaway home folder. Preflight walks the tree once instead of three times (#65); in strict mode it reads where a link out of the tree leads, and refuses only for what it finds there (#69). A client's own `Incident*` folder no longer stops native builds, and "Yes, and don't ask again" at a prompt no longer breaks the next run inside a git repository: preflight takes an untracked `.claude/settings.local.json` for your own. `scripts/lib/confine.sh` changed, so rebuild the Rust tools after updating: an older `audit-logs` build exits 4 until rebuilt, and the analysis fork falls back to the scripts meanwhile.
- **Host kernel and network attack surface.** Coverage for the host layer of Internet-facing nodes (validators, RPC nodes, keepers, indexers, self-hosted runners): KV-141, checklist 13 §13.14 (DEP-097..102) and a vulnerability-class playbook, `references/vuln-classes/kernel-attack-surface.md`, with locator recipes K1–K5 in `discovery/grep-commands.md`. It follows CVE-2026-98432 (NVD 2026-10-15, CVSS 9.8), a remote use-after-free in the Linux IPv4 TCP code present since 4.4, whose fix reached Ubuntu's kernels only in `-proposed` on 2026-11-02. The playbook is not Solana-specific: a read-only inventory of what a host has enabled against what it uses (§3), the reduction through configuration management (§4), and the protocol for the days when upstream has a fix and the distribution does not (§5). Its rules of engagement (§0): nothing runs on a host without the operator's go-ahead, and then read-only, and the audit machine never connects to a validator. The files cover the class, not the incident: no validator compromise through this CVE has been reported. With 7.7.0's thirteen items, its six bring the corpus to 1,465 items, and KV-141 to 141 known vectors.

### 7.7.0 (#56)

- **Per-project layout and a tool contract.** Intake records where your code lives in the Layout table of `audit_<n>/intake.md` (Q39, Q44), and the next interactive intake reuses it only on your yes, so `discovery/file-map.md` needs no edit. `audit-scan` and `audit-mem` take a `--contract=1` marker that an older build refuses: rebuild them after every update. The layout is #56 (#44); the contract marker came in 7.6.9 (#54).
- **Bundled steps run without asking.** Each `/auditor:*` command, and the root skill, starts with `scripts/preflight.sh`, which checks the working tree for Claude Code skills, commands, agents, hooks, MCP servers or settings beyond a few harmless keys. By default what strict mode would refuse is a note in the report, apart from the few shapes still refused in both modes, which Rules 11e and 11f list. Each command then pre-approves file reads, for any path, and of the bundled programs only those its steps use: run directories, read-only git, the collectors, the program snapshot, RPC reads, the lockfile recipes, the probe, dependency, SAST and build runners, the PoC runner, the PDF renderer, `audit-scan` and `audit-mem`; the analysis skill in the next entry pre-approves the analysis recipes, `jq-ro.sh` and `audit-logs`. Each of those programs checks its own arguments and itself writes only into run directories, the `audit-mem` store and scratch directories outside the tree, besides the toolchain caches its downloads fill. Nothing stops a run to ask a security question, and the report lists each limit instead: in native mode, the default unless intake, `AUDITOR_EXEC_MODE` or strict mode says otherwise, the project's builds and tests run on your machine without a prompt for each run; the isolated-mode self-check knows credentials only by their names and places; and preflight covers neither a session you start in such a tree for other work nor a command that a repository file has replaced; starting Claude Code with the strict launch line, which loads none of the repository's skills, commands or settings, rules both out ([Permissions and isolation](../README.md#permissions-and-isolation)). The confined entry points came in 7.6.2 (#47: `confine.sh`, `git-ro.sh`, `rundir.sh`), 7.6.3 (#48: the collectors, the program snapshot, `rpc-read.sh`, `report-to-pdf.sh`), 7.6.5 (#50: `run.sh --crate`, the isolation self-check, `probe.sh`), 7.6.6 (#51: `target.sh`, `deps.sh`, `sast.sh`) and 7.6.9 (#54: `audit-scan` and `audit-mem`), and preflight's first form in 7.6.4 (#49); 7.7.0 (#56) ran preflight in every command and added the pre-approvals (#37), and this entry gives default and strict mode as 7.7.2 has them.
- **`audit-logs` and the D&R analysis fork.** `audit-logs`, a third Rust tool, runs the detection & response recipes `profile.sh`, `frames.py` and `deltas.py` as one offline binary that prints what the scripts print, which a CI suite checks; the scripts run in its place when it is not built or its build is stale. `/auditor:hunt` and `/auditor:respond` run each analysis phase in `auditor:dnr-analyze`, a forked skill that runs the `incident-responder` agent; the skill's own list pre-approves only those recipes, `jq-ro.sh` and `audit-logs`. It came in 7.6.4 (#49), which closes #22.
- **Post-patch validation and live-probe rules.** `/auditor:patch --post-patch-validation` adds Trail of Bits post-patch validation. It is opt-in, never pre-approved, and runs only in isolated mode on a disposable clone, never on the client checkout; its result can only lower a fix tier. Intake question Q47 decides whether DEP-072 and DEP-073 may probe the project's live hosts and buckets: read-only, unauthenticated, and only those the client confirmed. Unanswered, or in `--auto`, it means no. It came in 7.6.7 (#52), which closes #27 and #34.
- **GitHub Actions workflow pass and runner procedures.** `audit-scan`'s workflow pass (`--workflows .github/workflows`) reads each workflow into trigger → job → step facts with a strict-subset YAML parser, and lists under `unknown` or `skipped` what it did not read instead of guessing. The locator recipes and their copies in KV-080, KV-116, KV-139 and KV-140 now match spellings they missed, such as quoted keys, value-first comparisons and agent CLI options before `-p`; the new R9 lists actions and reusable workflows pinned to a full SHA. The GitHub Actions playbook's §7 turns its pointers into procedures: pins and repointed tags (KV-080 Step 4), self-hosted runners (KV-080 Step 8) and OIDC trust policies (KV-140 Step 7). [docs/power-tools.md](power-tools.md#github-actions-workflow-analysis) pins zizmor by image digest and wheel hashes and describes CodeQL's `actions` queries. The recipe shapes came in 7.6.8 (#53, which closes #40); the workflow pass (#31) and the §7 procedures (#30) in 7.7.0 (#56).
- **Forensic readiness and the Cloudflare comparison.** Checklist 17 §17.6 (LM-066..068) checks that an incident can be worked up later: transaction history kept beyond the public RPC window, a deploy log that ties each upgrade to its commit and build hash, and archived account updates for fund-holding PDAs. A comparison with Cloudflare's security-audit skill adds availability review of dependency updates, toolchain pinning and published-file allowlists (SC-063..065), auth, rate and size limits before paid upstream calls (BE-133), retry and fee budgets for keepers and a quarantine for records a consumer cannot process (RS-022..023), and agent checks for signing approvals, MCP tool names, recalled memory and rendered output (AI-036..039). It is #56 (#24, #33): items 1,446 → 1,459 at 7.7.0.

## 7.6.1 (#46, 2026-10-24)

Follow-ups from the 7.6.0 reviews. No tag or GitHub Release: the 7.6.x patches close with 7.7.0.

- **CI checks.** An advisory job runs every check but the pull-request attribution check on macOS, with `/bin/bash` 3.2 and BSD tools. `check-frontmatter.sh` fails when Claude Code would read a command's, agent's or skill's frontmatter differently from what is written; `check-hygiene.sh` fails when the plugin root gains a load surface; `check-pipefail.sh` flags an early-exit reader on a pipeline whose producer's status matters; `check-corpus.sh` holds `plugin.json` and both marketplace entries to one version, and accepts a submodule only from `https://github.com/trailofbits/skills`. A weekly advisory workflow runs `claude plugin validate --strict`.
- **PoC verdicts bound to the assertions that ran.** `templates/poc` gets a committed `Cargo.lock`. Before anything compiles, `run.sh` refuses the crate's own build scripts and proc-macro packages, and before its final line it names the non-registry code it built. It exits 1 or 2 only when an assertion of that arm ran and did not hold; any other stop is exit 3. `/auditor:re-audit` records each finding's PoC re-run in `RE-AUDIT.md`, from the new `templates/re-audit.md`.
- **Detection & response hardening.** The RPC collector checks every write and records where an interrupted run resumes; the snapshot script checks every kept snapshot before any can match; `profile.sh`, `frames.py` and `deltas.py` share one input contract (`scripts/dnr/README.md`).
- **`install.sh` outside any repository.** With no path it installs to `~/.claude/skills/auditor-skill`, never into the current project, and moves an earlier install to a backup directory outside every skills directory ([Upgrading from 7.6.0 or earlier](../README.md#upgrading-from-760-or-earlier)).
- **Supply-chain recipes.** The §11.11 lockfile hints read tab-indented and CRLF lockfiles, pnpm v5 keys and merge commits; KV-137 and SC-054 fetch upstream only from an `https://` URL, into a Rule 11c copy that has no work tree.
- **Trail of Bits pin.** `vendor/trailofbits` moved from `82fe822` to `1f68e03`, trailofbits/skills `main` of 2026-10-15 (#45); plugin users received it with 7.6.1.

## 7.6.0 (#21, 2026-10-22)

[GitHub Release](https://github.com/solanabr/auditor-skill/releases/tag/v7.6.0). The Release page describes 7.6.0 as it shipped, and three of its upgrade notes no longer hold: isolated mode is not recommended since 7.7.2, a PoC build needs no recorded mode since 7.7.2, and hunt, respond and threat-model have pre-approved their bundled scripts since 7.7.0.

- **Detection & response, post-incident.** `/auditor:hunt` works through transaction history, program logs and Geyser/indexer exports with a written hypothesis ledger; `/auditor:respond` starts from a signature, address or alert and establishes whether the attack landed, how far it reached, and why. Verdicts follow a single [ladder](../references/detection-response/README.md#the-verdict-ladder-the-one-normative-copy); the response plan is for humans to carry out — the track acts on nothing. Ported Solana-native from Anthropic's defending-code-reference-harness.
- **History-seeded threat models.** `/auditor:threat-model --bootstrap` starts the threat model from what already went wrong: removed or quietly added account guards, reverts and fix commits in the target's history, a fork's distance from its parent, prior audit reports, post-mortems and incident records. One read-only, hardened collector (`scripts/threat-model/collect.sh`) gathers it; non-interactive runs stay offline, and every goal cites its evidence.
- **GitHub Actions trigger trust.** A CI playbook (`references/vuln-classes/github-actions.md`) for the shapes an outside account uses to reach a privileged job — comment-triggered commands without per-event author gating, expression and env-file injection, `pull_request_target` / `workflow_run` pwn requests with artifact and cache poisoning, and AI coding agents in CI — with KV-139/140, checklist 13 §13.13 (DEP-090..096), AI-034..035, read-only rules of engagement, and zsh-safe locator recipes backed by a fixture self-test.
- **Operating safety & dependency-update review.** A new OUTPUT-RULES Rule 11 covers five things. Target code runs in the execution mode chosen once at intake (Q46): isolated was recommended, native was allowed with a report caveat, and every PoC build needed `AUDITOR_EXEC_MODE`, without which `run.sh` stopped before building. Outside-service use is disclosed. Untrusted `.git/` checkouts are read without letting git run their config. Audit output never reaches git or a public CI log. Bundled scripts and tools run from the installation, never from a path in the audited repository. Checklist 11 §11.11 (SC-059..062) reviews what a dependency bump's *published code* actually changed, wired into `/auditor:diff-audit` and `/auditor:re-audit`. KV-077 and SC-005 now catch the hijacked `@solana/web3.js` 1.95.6 / 1.95.7 releases. 7.7.2 reversed the execution-mode advice: native became the default, and strict mode, which 7.6.0 did not have, is for code you don't trust.
- **PoC harness and CI.** `templates/poc/run.sh` builds from a scratch copy outside the audited tree with a pinned toolchain, and its exits 1 and 2 need a contract assertion that ran and did not hold; any other failure is inconclusive. CI's `corpus-check` runs all eight self-test suites, and `actions/checkout` is pinned to v7.0.1 by SHA, with `persist-credentials: false`.
- **Trail of Bits pin, reviewed and visible.** `vendor/trailofbits` moves from `cfe5d7b` (2026-06-30) to `82fe822` (2026-09-28) after a full delta review; upstream had since fixed a semgrep path that silently dropped two third-party rulesets and SARIF parsing that read CodeQL severities as zero errors. The pin is shown under Installation, fetched shallow, checked by CI against the gitlink, and moved by a monthly Dependabot PR that a maintainer reviews with `scripts/tob-delta-review.sh`; plugin users receive it with this release.

## 7.5.0 (#20, 2026-10-20)

[GitHub Release](https://github.com/solanabr/auditor-skill/releases/tag/v7.5.0).

- **Slot-as-clock coverage.** SIMD-0525 halved mainnet slot time to 200 ms (Oct 9, 2026) and Alpenglow (Oct 21, 2026) made `Clock.unix_timestamp` a leader-set value, so every timelock, vesting cliff, cooldown, oracle window, rate limit and interest constant denominated in slots now elapses in half the wall-clock time. KV-138 covers the class (the EVM learned it at the Merge with Compound's `blocksPerYear`; deployed lending programs still carrying `SLOTS_PER_YEAR = 63,072,000`, whether from an old-SDK build of SPL token-lending, the Save fork's literal or Kamino's legacy basis, now accrue 2.5x the configured APR), with SM-073..074, ECON-090..092, OPS-086..087, BE-132 and FV-073 as the per-domain checks.
